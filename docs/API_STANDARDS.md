# API Standards & Error Codes (Sprint 3.9.5)

This document describes the API standards, response envelopes, and error codes for CashFlow Enterprise.

## Overview

- All API responses must use a standard envelope. Success responses and error responses share a consistent structure to ease client parsing and observability.
- Each request should include a `x-correlation-id` header (generated by server if missing) and the same value returned in responses as `requestId`.
- Error codes are machine-friendly strings (ERR_*) and map to HTTP status codes.

## Response envelopes

Success response (200/201):

{
  "success": true,
  "message": "OK",
  "data": { ... },
  "timestamp": "2026-08-05T08:00:00.000Z",
  "requestId": "uuid"
}

Error response (4xx/5xx):

{
  "success": false,
  "message": "Validation failed",
  "errorCode": "ERR_INVALID_INPUT",
  "errors": [
    { "field": "email", "message": "Email is invalid" }
  ],
  "timestamp": "2026-08-05T08:00:00.000Z",
  "path": "/api/v1/users",
  "requestId": "uuid"
}

## Error code taxonomy

- ERR_INVALID_INPUT (400)
- ERR_UNAUTHORIZED (401)
- ERR_FORBIDDEN (403)
- ERR_NOT_FOUND (404)
- ERR_CONFLICT (409)
- ERR_INVALID_CREDENTIALS (401)
- ERR_TOKEN_EXPIRED (401)
- ERR_INTERNAL (500)
- ERR_DOMAIN (400) // placeholder for domain-level errors

Add new error codes as features are implemented. Use descriptive names prefixed with `ERR_`.

## Best practices

- Controllers should throw `HttpException` or the provided `AppError` for domain errors.
- Validation errors should be thrown by the global validation pipe and are returned in the `errors` array with `field` and `message`.
- Do not leak sensitive internals in `message` fields. Use `details` in logs only.

## Swagger & Documentation

- Error shapes are modeled in OpenAPI using `StandardErrorResponse`.
- Document `errorCode` values where appropriate in endpoint documentation.

## Implementation notes

- A centralized `ErrorService` and `AppError` class exist to make it easy to create classified errors and map to HTTP status codes.
- A global `HttpExceptionFilter` normalizes exceptions into the standard error envelope and attaches `requestId` from correlation middleware.
